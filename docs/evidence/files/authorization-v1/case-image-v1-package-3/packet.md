## Local implementation

- The upload intent and completion routes use the existing object-storage services only when `NODE_ENV=development` and `LABOS_CASE_IMAGE_LOCAL_ENABLED=1`. The new attachment route binds the current session tenant and Case to the existing atomic first-attachment service. Production builds keep these upload routes disabled.
- The local object-storage adapter uses opaque SHA-256 object IDs, signed 120-second create-only write/read capabilities, a 33,554,432-byte request ceiling, private local files, and bounded retrieval. The original bytes are unchanged. The browser receives no provider object key. The Case vault offers JPG/JPEG/PNG/WebP upload and uses the existing authorized open route for private images.
- After the first runtime pass, a bearer-token logging risk in local URL paths was corrected: PUT sends its capability in a header; authorized private open sets a short-lived HttpOnly, SameSite=Strict, path-scoped read cookie. Redirect and object paths now contain only the opaque digest. The route also checks the browser-facing `Host` against the configured local origin because Next normalizes `Request.url` to `localhost` internally; mismatched origins fail closed. A fresh disposable runner, route/database and authenticated HTTP replay passed after these corrections.
