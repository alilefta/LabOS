## Candidate Vercel containment policy for Product Owner disposition

Measured fact: the current protected Hobby Preview ran these bounded synthetic inputs with observed peak RSS 379.14 MiB and maximum measured single decode 687.47 ms. Contract arithmetic permits up to 33,554,432 original encoded bytes plus up to 150,000,000 RGB output bytes (or 50,000,000 grayscale), native workspace, Next/Node baseline, and transient/copy/GC retention. The native addon executes inside the long-lived function process; a JavaScript timer cannot be asserted to preempt a synchronous native call. Vercel's [current function limits](https://vercel.com/docs/functions/limitations) document a 2 GB Hobby default/maximum and configurable invocation duration, while [Fluid Compute](https://vercel.com/docs/fluid-compute) may share an instance across concurrent invocations. The build machine's 8,192 MiB shown by CLI is **not** function memory.

**Proposed, not approved:** keep the accepted byte/pixel/structural ceilings; admit at most **one active S001 decode per function instance**, with **zero waiters** and generic fail-closed overload before retrieval/buffering where production lifecycle permits. Do not claim a global concurrency cap from this per-instance gate or two-request test. Use a Vercel function `maxDuration` candidate of **30 seconds** for a future isolated validation request, subject to separately measured provider retrieval, transactional finalization and actual function configuration. This is an operational request ceiling, not an R001/S001 acceptance rule or a proven native-interruption guarantee. Keep the function's documented 2 GB Hobby memory envelope; do not claim a per-JPEG hard RSS cap or treat observed 379 MiB as worst case. Production approval requires a reviewed design for native in-process failure/OOM behavior, admission before byte retention, selected deployment memory/duration settings, overload response, and target-specific adversarial/retrieval measurements. Materially different plan, Node/N-API, addon/TurboJPEG build, memory class or concurrency behavior requires recalibration. The earlier Windows 10-second/384-MiB Job Object policy is not transplanted.
