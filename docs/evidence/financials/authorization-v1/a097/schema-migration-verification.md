## Non-UTC expiry evidence

The existing Invoice expiry column is `TIMESTAMP(3)`. On disposable PostgreSQL 17.11, the `a097-expiry-representation-disposable` suite passed in UTC and Asia/Baghdad sessions. Prisma wrote/read the same stored UTC wall value and its `>=` eligibility boundary agreed across sessions. A direct Date parameter inserted into `TIMESTAMPTZ(6)` shifted the epoch by three hours under Asia/Baghdad. SQL `"publicLinkExpiresAt" AT TIME ZONE 'UTC'` projected the authoritative Invoice column to the same absolute epoch in both sessions. The future audit writer must use that SQL projection inside its transaction; passing the client Date directly is not equivalent.
