## Settled representation

`CaseAssetFile.storageMode` describes the asset's **current** storage state. `LEGACY_URL_UNVERIFIED` retains its URL-only contract. Installed `MANAGED_PRIVATE` retains its original private-storage meaning and unavailable-content C2 read behavior. New `MANAGED_PUBLIC` means a validated managed asset whose current provider object is public-read. It requires a current version and null legacy URL/extension. Both managed modes require `clinicalPurpose` under the installed evidence guard. No historical C2 or evidence migration is changed.

`StoredFile.providerAccess` classifies the immutable physical object as `PUBLIC_READ` or `PRIVATE`. A null value is historical/unclassified and never implies private. The field has no default and no backfill. A new StoredFile insert must classify access; the existing immutable-row trigger freezes it, except for the pre-existing permitted live-Member non-null-to-null transition. A database enum label is an application assertion, not provider attestation: later attachment must establish the actual provider ACL and validation evidence before inserting a public file. Future private insertion requires genuine provider-private evidence under a separate gate.

The review-only SQL candidate is `prisma/migrations/20260929120000_case_public_provider_access_contract/migration.sql`. It adds the enums/field and updates installed trigger **functions in a new migration**. The C2 deferred asset trigger re-reads final state at commit and checks current version -> StoredFile provider access. New public requires `PUBLIC_READ`; new private requires `PRIVATE`. A new managed pointer also requires immutable clinical evidence matching the current file's source grant, Organization, Lab, provider/object key, the Case ID, and clinical purpose. An existing private row with null historical access is tolerated only while its current-version pointer is unchanged; it remains unavailable to content access until explicitly reconciled. An attempted public/private or evidence mismatch fails. The trigger disallows relabeling a managed asset as legacy; its only current-mode transition is an established `MANAGED_PUBLIC` asset moving to a different `MANAGED_PRIVATE` version. Other transitions, including legacy reconciliation, need a separate decision. The C2 composite FK still proves that the pointer belongs to the asset/Lab, and the version-to-physical-file relation remains immutable. The evidence-migration clinical-purpose trigger is extended to both managed modes. Trigger objects remain installed and deferred; no historical migration bytes are edited.

## DTO and application open contract (design, not implementation)

`CaseAssetSummary` retains the complete mixed collection and discriminates a third variant:

```ts
{ id, title, description, assetFileType, storageMode: 'MANAGED_PUBLIC' }
```

It has no `documentUrl`, file extension, provider/key, grant, current-version ID, or Case/Lab linkage. The existing `MANAGED_PRIVATE` variant stays metadata-only and unavailable. The legacy variant retains its URL/extension only when complete. Detail, draft, metadata, and edit-form projections must not add a direct managed URL; the public variant's UI can offer an explicit Open action. No image/video prefetch, thumbnail, or automatic lightbox URL is implied by Case detail rendering. General Case saves still omit asset commands and omission never deletes an asset.

The later Case-only open operation accepts strict identifier-only `{ caseId, assetId }`. It derives actor/tenant from the authenticated session; freshly applies existing `case.read` against authoritative Case/Organization/Lab/Member and exact active Staff assignment; only then resolves the asset, current version, StoredFile, and provider key in the same tenant. It requires `MANAGED_PUBLIC`, `PUBLIC_READ`, a valid current managed relationship, and approved validation evidence. It may return the direct public URL in a narrow no-store response for an explicit user open. The URL must not appear in normal Case DTOs, page metadata, prefetch/hydration, logs, telemetry, audit, email, or notifications. Generic unavailable/not-found responses conceal missing, foreign, unassigned, unclassified, and mismatched resources; unauthenticated requests follow normal authentication failure. Do not derive an open URL from client input or a legacy grant URL.

LabOS authorizes application discovery and opening. UploadThing `public-read` allows anyone already holding the direct URL to retrieve bytes without LabOS authorization. URL minimization reduces exposure, not provider confidentiality. This public operation must not call C3 `ISSUED` or fabricate expiry. C3 retains genuine signed/private issuance meaning and remains inactive for public retrieval. If a public-open audit is required, decide the smallest truthful allowlisted event contract in the later open-operation slice; do not weaken C3.

## Migration safety and rollback

- Structural delta: one added `CaseAssetStorageMode` value, one new `StoredFileProviderAccess` enum, one nullable `StoredFile.providerAccess` column, and new/updated trigger functions. No table, FK, URL, current-version, or legacy-row rewrite. Existing indexes and C2 audit constraints remain.
- Before application, attest the exact target and migration history, inspect current managed rows/access nulls and trigger definitions without URLs or provider keys, compare Prisma-modelled SQL with this candidate, and review SQL ordering. Existing rows must remain untouched. Do not infer there are zero managed rows from development checkpoint history.
- PostgreSQL cannot use the added `MANAGED_PUBLIC` enum label until its transaction commits. The candidate therefore commits that enum statement before opening a transaction for the remaining DDL. If the second transaction fails, the enum label remains installed while its remaining DDL rolls back; no new public rows or application capability are activated. Migration history may need an explicitly reviewed repair before retry. Enum-value rollback is not a simple down migration. If new rows exist, disable public-write/open behavior and preserve data. Any later structural rollback requires a separately approved data-aware plan; never relabel public rows private.
- Future public-to-private replacement inserts a newly attested `PRIVATE` StoredFile and immutable version, then switches the same `CaseAssetFile.id` current pointer and mode to `MANAGED_PRIVATE` in **one guarded UPDATE statement** inside the transaction. The installed deferred guard evaluates each changed row event, so splitting pointer and mode into separate UPDATE statements is outside this candidate's accepted write shape. Old versions keep `PUBLIC_READ`; switching the pointer does not revoke old public URLs or delete old provider bytes. Private opening must reject null/public access and has no public fallback. The current Case clinical evidence trigger is scoped to N-FILE-110; a future replacement boundary must separately establish compatible immutable validation evidence before its private pointer can commit. Provider retirement requires its own authority.

## Focused verification design for later gates

1. Prisma validation and generated structural SQL comparison; candidate migration checksum and unchanged hashes for installed C2/evidence migrations.
2. Disposable PostgreSQL: enum addition and subsequent trigger installation order; failure after enum commit leaves only the new label, requiring controlled migration-history repair. Legacy rows survive unchanged; historical managed/private null rows survive unchanged but do not open; new StoredFile null access rejects; provider-access update/delete rejects while live-Member null transition still works.
3. Deferred transaction tests: asset insert -> file/version/pointer commit for public with exact Case/object validation evidence; absent or other-Case/object/grant evidence, absent pointer, URL fields, absent purpose, private/public mismatch, wrong version/tenant, and null classification reject. Replacement preserves asset ID and immutable public version, requires evidence for the new private pointer, rejects private pointer to public/null file, and rolls back all partial changes. Reject private/public -> legacy, private -> public, and public -> private with the same version pointer.
4. DTO tests: complete mixed arrays in detail/draft, managed public/private variants contain no provider fields or URL, legacy display remains; ordinary Case form omission preserves all IDs/versions.
5. Open-operation tests when separately authorized: authorization precedes provider/file lookup; same-tenant assigned Staff and fixed-bundle non-Staff rules; unauthenticated, foreign, unassigned, unclassified and mismatched denials; no URL in logs/telemetry/metadata, no automatic prefetch, no C3 `ISSUED`, and no public fallback from private mode.

This authoring task establishes no PostgreSQL runtime result and no application/provider activation. Separate V3 SQL review, disposable database verification, normal-development migration approval, application open implementation, and provider/attachment gates follow in bounded tasks.
