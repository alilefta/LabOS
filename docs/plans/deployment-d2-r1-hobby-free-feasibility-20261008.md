## R3 — repository compatibility

- `package.json` declares `next` 16.3.3, Prisma/adapter-pg 7.x, Better Auth 1.x, Julusian 3.0.1, R2 SDK and UploadThing. `pnpm build` is `next build`; `pnpm migrate` is **`prisma migrate dev`**, unsuitable for hosted schema installation. No committed LabOS Vercel link, `vercel.json` or GitHub Actions migration runner was found. The exact lockfile and migration chain must be pinned/checked at deployment.
- `lib/prisma.ts` constructs the app client from `DATABASE_URL` via `PrismaPg`; `lib/auth.ts` Better Auth Organizations shares that client and reads `BETTER_AUTH_SECRET`/`BETTER_AUTH_URL`. `prisma.config.ts` reads `DIRECT_URL` for migrations. Existing role grants must cover actual Better Auth/org DML and triggers, not merely an initial login.
- `next.config.ts` externalizes Julusian and traces exact Linux x64 addon and adjacent TurboJPEG library for the completion route. `identity.ts` requires same-process Linux x64, Node 24, N-API 10, `/proc/self/maps`, the reviewed package version and hashes. Accepted isolated [Vercel Preview S001](../evidence/files/authorization-v1/n-file-110-case-asset-create/s001-core-preview-20261003-157cb99a8d/packet.md) proved synthetic core native execution with limitations; [R2-06](../evidence/files/authorization-v1/r2-06-production-s001-case-runtime/packet.md) proved the complete synthetic Case chain in disposable Linux/Docker/R2. Neither proves the full intended Hobby deployment bundle, actual protected HTTP/UI flow or restricted Free role.
- `modules/labos-files/object-storage/config.ts` reads four `LABOS_R2_*` server env names and binds the semantic ObjectStorage port to R2. `CASE_OBJECT_STORAGE_UPLOAD_ACTIVE` is hard-coded false; intent/completion routes deny. Keep R2 private, with a verification-specific bucket/key and exact CORS origins separate from local development. No R2 credential or signed URL enters DTOs/logs.
- Current `next.config.ts` has `logging.fetches.fullUrl: true`, which needs a bearer-URL logging audit before sensitive upload/read exposure; no leak is asserted without a path. The optional whole-snapshot TypeScript check in R2-06 exhausted Node heap and remains **INCONCLUSIVE**. No current full `tsc` or `next build` PASS for this checkout is established. A separately authorized affected type/build gate and target-native bundle test precede deployment/activation; D2-R1 does not repair or run a generating build.

## R4 — proposed $0 topology and isolation

One future Vercel Hobby project may use **All Deployments + Vercel Authentication** for both its Production-classified pre-launch alias and Preview URLs. It is a *verification* project, not the D1 paid-production project. Use synthetic, non-clinical data only. Ordinary generic PR previews have no writable DB/R2 credentials; a selected protected branch/deployment gets restricted app `DATABASE_URL`, environment-specific Better Auth secret/base URL and verification-only R2 credentials. The Production-classified initial alias is protected exactly like Preview; it is not customer production.

One **new, separate Supabase Free verification project**, if the account has a second active slot, has a non-owner custom app LOGIN; the current local-development project and credentials stay untouched. A separate DDL owner installs only separately approved migrations **before** application deployment through a separately approved execution path; no build/request runs migrations. No migration-owner `DIRECT_URL` is configured in Vercel, including at build time. D1's GitHub Actions candidate remains unselected pending branch/environment approval, secret-custody and direct-IPv6/session-pooler network proof. The verification R2 bucket/credential is distinct from local and future production; remain within Standard-storage free allowances only if measured [R2 usage](https://developers.cloudflare.com/r2/pricing/) permits. Vercel/Supabase/R2 quotas and account state can prevent actual $0; this packet promises no zero bill.

No clinical data, production database copy, normal-development credential rotation, cleanup DELETE, N-FILE-110 activation, or paid production launch is part of this topology.
